# Wingoat Gamification Widget Integration

This guide explains how an iGaming operator embeds the player gamification widget in a sportsbook, casino, poker, slots, or predictions product.

## 1. Embed the IIFE build

Use the one-file IIFE build when the operator cannot use ES modules or a bundler.

```html
<link rel="stylesheet" href="https://cdn.example.com/wingoat/gamification-widget.css" />
<script src="https://cdn.example.com/wingoat/gamification-widget.iife.js" defer></script>
```

Then add a mount node:

```html
<div
  data-wingoat-widget
  data-operator-id="operator-caliente"
  data-player-token="PLAYER_JWT_FROM_OPERATOR"
  data-locale="es-PE"
></div>
```

The operator owns player authentication and must provide a short-lived `data-player-token` generated by its backend.

## 3. Public JavaScript API

The API below is the integration contract for the hosted widget runtime.

```ts
window.WingoatGamificationWidget.init(selectorOrElement, config?)
window.WingoatGamificationWidget.destroy()
window.WingoatGamificationWidget.on(eventName, handler)
window.WingoatGamificationWidget.updatePlayer(playerPatch)
window.WingoatGamificationWidget.openTab(tabId)
```

### `init(selectorOrElement, config?)`

Mounts the widget into a DOM node or selector.

```js
window.WingoatGamificationWidget.init('[data-wingoat-widget]', {
  operatorId: 'operator-caliente',
  locale: 'es-MX',
  tabsOrder: ['home', 'missions', 'shop', 'social', 'streak', 'ranking', 'tournaments', 'predictions', 'news'],
});
```

### `destroy()`

Unmounts the widget and removes listeners created by the widget.

### `on(eventName, handler)`

Subscribes to widget events. Returns an unsubscribe function.

```js
const off = window.WingoatGamificationWidget.on('levelUp', function (payload) {
  console.log('Player leveled up', payload.level);
});
off();
```

### `updatePlayer(playerPatch)`

Patches visible player metadata after operator-side changes.

```js
window.WingoatGamificationWidget.updatePlayer({
  coins: 2400,
  unreadNotifications: 2,
});
```

### `openTab(tabId)`

Programmatically opens one of the 9 widget tabs.

```js
window.WingoatGamificationWidget.openTab('missions');
```

## 4. Configuration

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `operatorId` | `string` | Yes | Tenant/operator identifier. Must match backend tenant config. |
| `playerToken` | `string` | Yes | Short-lived player token issued by the operator. Never expose betting credentials. |
| `locale` | `string` | No | BCP-47 locale such as `es-PE`, `es-MX`, `pt-BR`, `en-US`. |
| `tabsOrder` | `TabId[]` | No | Order of the 9 tabs. Unknown tab IDs are ignored. |
| `theme.accentPrimary` | `#0AF784` only | No | Currently fixed by product strategy; operators may not replace the green accent. |
| `theme.logoUrl` | `string` | No | Optional operator logo in surfaces that support co-branding. |
| `theme.radiusScale` | `compact \| default` | No | May reduce radius, never exceed 24px on rectangular cards. |

Theme overrides are intentionally limited to preserve the crypto-futurist identity.

## 6. Events emitted

| Event | Payload | When |
| --- | --- | --- |
| `levelUp` | `{ playerId, level, rewards }` | Level-up animation starts. |
| `rewardClaimed` | `{ playerId, rewardId, kind }` | Player collects a reward. |
| `missionClaimed` | `{ playerId, missionId, xp, coins }` | Player claims a completed mission. |
| `tabOpened` | `{ tabId }` | Active tab changes. |
| `notificationOpened` | `{ notificationId, kind }` | Player opens a notification. |
| `postPublished` | `{ postId, pendingReview }` | Feed post is submitted. |
| `betCopied` | `{ postId, pickId, teams, prediction, odds, totalOdds?, legs? }` | Player copies a shared bet or combined ticket to the operator slip. |
| `tournamentRegistered` | `{ tournamentId }` | Player confirms tournament registration. |
| `error` | `{ code, message, retryable }` | Widget cannot complete an action. |

## 7. Troubleshooting

| Symptom | Check |
| --- | --- |
| Widget does not appear | Confirm the mount node exists before `init()` and CSS is loaded. |
| Blank widget | Check browser console for blocked CDN, CSP, or invalid token errors. |
| Player data missing | Confirm `operatorId` and `playerToken` match the backend tenant. |
| Styles look wrong | Ensure `gamification-widget.css` is included exactly once and not overridden globally. |
| Mobile layout clipped | Mount inside a container that allows `width: 100%` and avoids `overflow: hidden` on ancestors. |
| Events not firing | Register listeners before opening tabs/modals that emit events. |
| IIFE too large for policy | Use the ES module build and serve split chunks with long cache headers. |

## 8. Security and ownership boundaries

- The widget does not manage deposits, withdrawals, betting auth, self-exclusion, account deletion, or responsible gambling tools.
- The operator is responsible for player identity, legal account flows, payments, and problem-gambling controls.
- The widget token should be short-lived and scoped only to gamification APIs.
